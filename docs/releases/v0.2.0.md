# v0.2.0 — the VRM session, packaged

**Release status:** the tag `v0.2.0` is cut from the commit that adds this record,
after a green dry run of the [release workflow](../../.github/workflows/release.yml)
on `main`.

## Objective

Publish the first package with a real consumer: the
[native VRM session](../architecture/VRM_SESSION.md) that `hydra-toon`'s
`toon-viewport-vrm` builds against. It does not close Runtime Phase A and does not
freeze the ABI.

## What ships

For `cy2026` / `usd` on Windows x86_64 and Linux x86_64:

| Package | Contents | Dependencies |
| --- | --- | --- |
| `avatarRuntime` | the core | none |
| `avatarVrmSession` | the core, the session's adapters and `avatarVrmSessionCheck` | motion 0.5.4, `vrmRig` and `vrmSchemaSdk` 0.12.0, OpenUSD from the runtime |

Both provide the `AvatarRuntime` CMake package, so a consumer pins one of them. The
session is requested as `find_package(AvatarRuntime 0.2 COMPONENTS vrm_session)` or
`find_package(AvatarVrmSession 0.2)`. The release lane checks a consumer of the session
with `ost library verify-consumer` on Windows and by building and running the
repository's installed consumer on Linux.

## Compatibility

- **ABI:** experimental [revision 5](../contracts/ABI.md), unchanged.
- **CMake:** `SameMinorVersion`, so a request for 0.1 no longer finds this package.
- **Owners:** a source build of these adapters still accepts `vrmSchema` 0.10 or newer
  when it provides contract v2 and the spring API. The package is built against 0.12.0.

## Adapters at this release

| Adapters | Owners | State |
| --- | --- | --- |
| motion, USD, motion USD, VRM USD, spring, VRM session | motion 0.5.4, VRM 0.12.0 | in `avatarVrmSession` |
| VRM expression and LookAt | `vrmRig`, `vrmSchema` | source only |
| MMD | `mmdPhysicsAdapter` 0.3 | source only; the owner library is not published |
| Stage Runner, physics USD, MMD session | Stage Runner and physics 0.1 | source only |

## Known limitations

- The session selects pose only: expressions, gaze and node constraints are not
  evaluated. Scaled spring rigs are refused.
- Resident rendering was checked on Windows only, with the renderer on the `lookdev`
  runtime and this package built for `usd`. See the
  [capability matrix](../reference/CAPABILITY_MATRIX.md#avatarvrmsession-package-2026-11-01).
- The session has no pull request lane; only the release workflow builds it.
- macOS is not a release target. Hydra publication, recording publication, OpenExec,
  inspect/replay tools and connector intake are not implemented.
