# v0.1.0 — the core, packaged

**Release status:** the tag `v0.1.0` is cut from the commit that adds this record,
after a green dry run of the [release workflow](../../.github/workflows/release.yml)
on `main`.

## Objective

The first release. It establishes hosted CI and a release lane, and it publishes
the dependency-free core by digest. It does not close Runtime Phase A and does
not freeze the ABI.

## What ships

`avatarRuntime`, the `AvatarRuntime::avatarRuntime` CMake package, for `cy2026` /
`usd` on Windows x86_64 and Linux x86_64. The [changelog](../../CHANGELOG.md) lists
its contents, and the source archive holds the optional adapters and host tools.

## Compatibility

- **ABI:** experimental [revision 5](../contracts/ABI.md). A provider or consumer
  built against another revision is refused and must be rebuilt.
- **CMake:** the package uses `SameMinorVersion`, so `find_package(AvatarRuntime 0.1)`
  finds any 0.1.x.
- **Dependencies:** none. The core needs no OpenUSD, Hydra, OpenExec or format
  library at build or run time.

## Adapters at this release

Adapters build from source against installed owners. Which of those owners can be
pinned decides when an adapter can join the package:

| Adapters | Owners | Owner packages |
| --- | --- | --- |
| motion, USD, motion USD | motion 0.5.4 | published as libraries |
| VRM, VRM USD, spring, VRM session | `vrmRig`, `vrmSchema` 0.10 or newer | inside `execVrm` and `vrmSchema`; not separately pinnable from a registry on `usd` |
| MMD | `mmdPhysicsAdapter` 0.3 | not published; build it from `usd-mmd-plugins` |
| Stage Runner, physics USD, MMD session | Stage Runner and physics 0.1 | first releases follow this one |

The MMD adapter was built and tested locally against `mmdPhysicsAdapter` from the
`usd-mmd-plugins` `v0.3.0` tag. The other adapters were not rebuilt for this release.

## Known limitations

- Hydra publication, recording publication, OpenExec, inspect/replay tools and
  connector intake are not implemented.
- Representative PMX/VMD and renderer acceptance remain open; see the
  [roadmap](../roadmap/current.md).
- The hosted lanes run the core's contract tests. Adapter evidence stays local and
  opt-in, as the [capability matrix](../reference/CAPABILITY_MATRIX.md) records.
- macOS builds and passes the core tests in CI, but is not a release target.
