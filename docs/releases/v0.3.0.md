# v0.3.0 — the VRM session, on screen

**Release status:** the tag `v0.3.0` is cut from the commit that adds this record,
after a green dry run of the [release workflow](../../.github/workflows/release.yml)
on `main`.

## Objective

Complete the [native VRM session](../architecture/VRM_SESSION.md) and connect it to a renderer.
A real VRM goes into one session, motion, LookAt, expression and spring evaluate there, and
`hydra-toon` receives the committed state and draws it. It adds no evaluator and does not freeze the ABI.

## What ships

For `cy2026` / `usd` on Windows x86_64 and Linux x86_64:

| Package | Contents | Dependencies |
| --- | --- | --- |
| `avatarRuntime` | the core | none |
| `avatarVrmSession` | the core, the session's adapters and `avatarVrmSessionCheck` | motion 0.5.4, `vrmRig` and `vrmSchemaSdk` 0.12.0, OpenUSD from the runtime |

New in the session since 0.2.0:

- Expressions and LookAt, selected explicitly, from the host or from the clip.
- The [evaluated-state contract](../contracts/EVALUATED_STATE.md#4-consumer-contract) for consumers.
- Tested failure, recovery, destroy/recreate and two avatars in one thread.

[Choosing a package](../architecture/PROJECT_LAYOUT.md#packaging) is now enforced. A consumer pins one,
finds it with `find_package(AvatarVrmSession 0.3)` or `find_package(AvatarRuntime 0.3)`, and a
combination is refused with a message naming the choice.

## Compatibility

- **ABI:** experimental [revision 5](../contracts/ABI.md), unchanged. The freeze stays deferred; the
  [review](../contracts/ABI.md#4-change-candidates-reviewed-for-v030) lists what is open.
- **CMake:** `SameMinorVersion`, so a request for 0.2 no longer finds this package.
- **Session API:** `Session::Advance` gains an overload taking observations, and `SessionConfig` gains
  the face selections. Existing calls keep their meaning. The API has no compatibility policy yet.

## Known limitations

- Expressions and gaze on real avatars used generated input, and no real avatar's expressions bound
  a material, so a material override reaches a renderer only as far as the generated fixture's state shows.
- The renderer check ran on Windows only, with the renderer on the `lookdev` runtime, this package built
  for `usd`, and locally built VRM plugins. Pixels were not compared numerically.
- Node constraints are [not evaluated](../architecture/VRM_SESSION.md#node-constraints), and scaled spring
  rigs are refused.
- `scripts/compare_avatar_state.py` has no consumer feeding it yet, so Hydra/direct agreement is not shown.
- macOS is not a release target. Hydra publication, recording publication, OpenExec, inspect/replay tools
  and connector intake are not implemented.
