# v0.4.0 — the MMD session, as a package

**Release status:** the tag `v0.4.0` is cut from the commit that adds this record, after a green dry run of the
[release workflow](../../.github/workflows/release.yml) on `main`.

## Objective

Show that the runtime is not VRM-shaped: a real PMX and VMD load, play, reset and feed physics back from an
installed package, compared with the owner, with no format-specific change to core. It adds no evaluator phase and
does not freeze the ABI.

## What ships

For `cy2026` / `usd` on Windows x86_64 and Linux x86_64:

| Package | Contents | Dependencies |
| --- | --- | --- |
| `avatarRuntime` | the core | none |
| `avatarVrmSession` | the core, the session's adapters and `avatarVrmSessionCheck` | motion 0.5.4, `vrmRig` and `vrmSchemaSdk` 0.12.0, OpenUSD from the runtime |
| `avatarMmdSession` | the core, the session's adapters and `avatarMmdSessionCheck` | motion 0.5.4, physics 0.1.2 with `physicsJoltSixDof`, Stage Runner 0.1.0, MMD 0.3.2, OpenUSD from the runtime, and a Jolt SDK the consumer builds |

A consumer pins one and finds it with `find_package(AvatarMmdSession 0.4)` or the `mmd_session` component of
`AvatarRuntime`. **The MMD session needs a deterministic Jolt 5.5.0 SDK**, built with the options
[its boundary](../architecture/MMD_SESSION.md#package-boundary) names. The package checks them and refuses any other
build. `ost library verify-consumer` cannot name that SDK, so this package has no `package_contract`.

What it runs and refuses is in the [supported subset](../reference/CAPABILITY_MATRIX.md#mmd-session-supported-subset).
Full MMD compatibility is not claimed.

## Decisions

- **[RT-O3](../contracts/EVALUATOR.md#6-rt-o3-the-existing-phases-fit):** the existing phases fit both sessions, with no phase extension.
- **[RT-O6](../architecture/FRAME_LIFECYCLE.md#rt-o6-one-world-one-session):** decided for one world per session. Interpolation and tick/display provenance wait for the freeze, and shared participants for the several-avatars gate.

## Compatibility

- **ABI:** experimental [revision 5](../contracts/ABI.md), unchanged. The freeze stays deferred.
- **CMake:** `SameMinorVersion`, so a request for 0.3 no longer finds this package.
- **State format:** `--state-output` gains a `uvs` channel for primary vertex UVs.

## Known limitations

- Physics runs on Jolt, not MMD's Bullet, so motion can differ from MMD. Agreement with the owner covers composition, not the solver, and how physics looks was judged only by eye, on one model.
- Real models ran on Windows only. Generated state is equal across platforms for this fixture; other assets are not assumed to agree.
- No local real model has an after-physics bone, so that path rests on the generated fixture.
- Material values are delivered but not compared with the owner.
- One avatar in one world. No seek, loop or speed control, no additional UV channels, and flip and impulse morphs have no output.
- The private test motion names bones and morphs many of the models lack, so those keys are dropped, and those models showed less of it.
- macOS is not a release target. Hydra publication, recording publication, OpenExec, inspect/replay tools and connector intake are not implemented.
